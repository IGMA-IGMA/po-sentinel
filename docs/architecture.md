# Архитектура PO Sentinel

## Общая схема

    +---------------------+        +---------------------+
    |  Oracle EBS (OeBS)  |        |  Внешние API        |
    |  PO, AP, INV        |        |  (уведомления)      |
    +----------+----------+        +----------+----------+
               |                              ^
               | SQL / PL/SQL                 |
               v                              |
    +---------------------+        +----------+----------+
    |  Oracle Database    |<------>|  Python-скрипты     |
    |  индексы, MViews    |        |  extract, notify    |
    +----------+----------+        +---------------------+
               |
               | источник данных
               v
    +---------------------+
    |  Oracle BI          |
    |  дашборды, отчёты   |
    +---------------------+

## Слои

### 1. Источник данных — Oracle E-Business Suite
Стандартные таблицы закупок, счетов и организаций:
PO_HEADERS_ALL, PO_LINES_ALL, AP_INVOICES_ALL, INV_ORGANIZATIONS и другие.

### 2. Аналитический слой — Oracle Database
SQL-витрины, индексы и материализованные представления для быстрой выборки
проблемных заказов по заданным правилам.

### 3. Интеграция — Python
Скрипты выгружают данные из Oracle, обмениваются с внешними API и отправляют
уведомления ответственным сотрудникам.

### 4. Расширение OeBS — PL/SQL + OAF
PL/SQL-пакет реализует правила выявления проблем, конкурентная программа
запускает обработку по расписанию, OAF-страница показывает результат внутри EBS.

### 5. Визуализация — Oracle BI
Дашборды и отчёты: динамика задержек, топ проблемных поставщиков, суммы
потенциальных потерь, статусы заказов.

## Правила выявления проблемных заказов

- Просроченная поставка: ожидаемая дата поступления < текущей даты.
- Отсутствие поступления: заказ подтверждён, но поступления нет.
- Расхождение цены: цена в счёте отличается от цены в заказе.
- Задолженность по счетам: счёт не оплачен после срока.

## Расширение OeBS (PL/SQL)

Каталог `oebs/plsql/`:

| Файл                             | Назначение                                                 |
|----------------------------------|------------------------------------------------------------|
| `xx_problem_orders_pkg.sql`      | Спецификация пакета: API для OAF и конкурентной программы  |
| `xx_problem_orders_pkg_body.sql` | Тело пакета: правила выявления проблемных заказов          |
| `xx_problem_orders_conc.sql`     | Регистрация конкурентной программы и расписания в EBS      |

### API пакета `xx_problem_orders_pkg`

- `get_problem_orders(p_org_id, p_date_from, p_date_to, p_vendor_id)` —
  пайплайновая функция, возвращает коллекцию проблемных заказов.
- `get_problem_order_by_id(p_po_header_id)` — детализация одного заказа
  для OAF-страницы.
- `evaluate_order(p_po_header_id)` — проверяет один заказ по всем правилам.
- `refresh_problem_orders` — обновляет материализованные представления.
- `refresh_and_notify(p_org_id, p_notify)` — обновляет MV и рассылает
  уведомления (точка входа для конкурентной программы и кнопки «Обновить»).
- `notify_responsible(p_org_id)` — инициирует отправку уведомлений.
- `count_problem_orders(p_org_id)` — количество проблемных заказов.
- `get_supplier_problem_amount(p_vendor_id)` — сумма проблем по поставщику.

### Конкурентная программа

- Executable: `XX_PROBLEM_ORDERS` (SQL*Plus).
- Program: `XX_PROBLEM_ORDERS_REFRESH`.
- Параметры: `P_ORG_ID` (опционально), `P_NOTIFY` (Y/N).
- Расписание: job `XX_PROBLEM_ORDERS_DAILY` — ежедневно в 02:15.

## OAF-страница

Каталог `oebs/oaf/`:

| Файл                       | Назначение                                             |
|----------------------------|--------------------------------------------------------|
| `XXProblemOrdersPG.xml`    | Page definition: таблица проблемных заказов + поиск    |
| `XXProblemOrdersCO.java`   | Controller: поиск, обновление MV, экспорт в CSV        |
| `XXProblemOrdersVO.xml`    | View Object: читает данные через PL/SQL-функцию        |

### Функциональность страницы

- Поиск по организации, поставщику и диапазону дат создания.
- Таблица с флагами проблем: просрочка, нет поступления, расхождение
  цены, не оплачен.
- Колонка `ProblemCount` — сколько правил сработало.
- Кнопка «Обновить» вызывает `refresh_and_notify` из PL/SQL-пакета
  и перечитывает данные.
- Кнопка «Экспорт CSV» формирует файл из текущей выборки.
- VO читает данные напрямую из `xx_problem_orders_pkg.get_problem_orders`
  (пайплайновая функция) — единый источник правды с MV.

### Подключение в EBS

1. Установить PL/SQL-пакет (`@oebs/plsql/...`).
2. Создать OAF-страницу через XML Importer или скопировать файлы
   в `$JAVA_TOP/xx/oracle/apps/po/sentinel/webui/`.
3. Зарегистрировать функцию в `FND_FORM_FUNCTIONS` с типом `OAF`,
   указав `XXProblemOrdersPG`.
4. Добавить функцию в меню закупок или в кастомное меню.

## Взаимодействие с Python

Конкурентная программа после пересчёта MV вызывает Python-скрипт
`python/notify.py` (через хост-команду или внешний планировщик) для
отправки сводки по email и webhook. Данные для сводки берутся из
`XX_MV_SUPPLIER_SUMMARY`.
